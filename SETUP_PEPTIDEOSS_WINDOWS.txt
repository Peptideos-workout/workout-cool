Workout.cool — production is Vercel, not this PC
================================================

Production site: https://workouts.peptideos.us
GitHub repo: https://github.com/zomegz1/workout-cool (branch main)
Vercel project: workout-cool (its own project; PeptideOS stays a separate Vercel app)

How production updates ship
---------------------------------------------------------------------------

1. Edit the app in the cloud (Cursor cloud or GitHub) on zomegz1/workout-cool.
2. Push to main. Vercel builds that branch with `pnpm run vercel-build` (`next build` only).
   The Vercel build does not run Prisma migrate and does not seed sample data.
3. Schema changes for `wc` are applied by hand: GitHub → Actions → "migrate-wc" → Run workflow.
   That workflow runs `npx prisma migrate deploy` with the DIRECT_DATABASE_URL secret
   (direct host db.<ref>.supabase.co:5432). It never runs on push and never seeds.
4. Keep these Vercel env values:
     SEED_SAMPLE_DATA=false
     SKIP_DB_MIGRATE=1
     NEXT_PUBLIC_APP_URL=https://workouts.peptideos.us
     BETTER_AUTH_URL=https://workouts.peptideos.us
   DATABASE_URL on Vercel is the Supabase pooler URI with pgbouncer=true and connection_limit=1.
   DIRECT_DATABASE_URL is for the migrate workflow only, not the pooler.

Shared Supabase project with PeptideOS. Workout.cool tables stay in schema `wc`.
Do not merge the repos. Do not commit .env.

PeptideOS (dashboard only, do not edit that repo for this host move):
  NEXT_PUBLIC_WORKOUT_COOL_URL=https://workouts.peptideos.us
  SUPABASE_JWT_SECRET must match the value on the workout-cool Vercel project.

Google OAuth authorized redirect:
  https://workouts.peptideos.us/api/auth/callback/google

Optional local use (not production)
---------------------------------------------------------------------------

docker-compose.yml and the Dockerfile remain in the repo for a local container.
They are not how workouts.peptideos.us is hosted.

  cd C:\Users\administrators1\Desktop\workout-cool
  copy .env.example .env
  npx pnpm install
  npx pnpm dev

Local NEXT_PUBLIC_APP_URL / BETTER_AUTH_URL can be http://localhost:3010.
If DATABASE_URL points at Supabase, you do not need the Docker Postgres service.

Migrations against the shared database, from this PC, if you are not using the GitHub workflow:
  npm run db:migrate:direct
Use the direct URI (port 5432), never the pooler, for migrate.

Leave SEED_SAMPLE_DATA=false unless you intend to import the sample CSV.
pnpm tip: npm install -g pnpm, otherwise npx pnpm ...
